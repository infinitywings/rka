**Reference:** discovery workflow `wqicgntwi` (2026-05-31).
Design synthesis: post-segment silent stall = bg thread blocked
mid `compiled.invoke()` on SDK subprocess pipe wait. Fix:
`_WatchdogProbe` (before/after checkpoint-id + status +
interrupt-set comparison) + single bounded retry +
escalate-on-deterministic-stall + runner-side hardening (wrap
post-invoke inspection + remove silent `or 'complete'` default).

**Branch:** `agentic`.
**Files:**
- `orchestrator/orchestrator/server.py` — `_WatchdogProbe`,
  `_read_checkpoint_id`, `_probe_advanced`, `_cache_sync`,
  integration in `_background_segment`, refactor inline
  `_drive_segment_bg` to use shared helper.
- `orchestrator/orchestrator/runner.py:_execute_segment` —
  wrap post-invoke inspection in try/except; remove silent
  `or 'complete'` default; emit explicit `terminal_state` for
  graceful no-progress returns.
- `orchestrator/tests/test_watchdog.py` (new) — 8 tests per
  the synthesis: happy-path, transient-stall-recovered,
  deterministic-stall-escalates, saver-path-None-degrades,
  cache-sync idempotent, cache-sync writes-when-differs,
  no-retry-when-exception, set-identity catches
  park-then-answer race.
- `orchestrator/tests/test_invariants.py` — test-count floor
  bump.
- `CHANGELOG.md` — `[agentic — 2.6.0+agentic.1]` Unreleased.

  subsection.

**Test plan:** 8 new tests + 2 invariant assertions.

resume code path PR2 doesn't touch — disjoint files, no merge

## 9. Cross-Branch Coordination

### 9.1 Merge order

After all four PRs land:

1. `main` is at `2.6.2`.
2. `agentic` absorbs `main` via `git merge origin/main`.
   Bookkeeper invariant verified post-merge.
3. Agentic branch absorbs the follow-on adapter-side polish
   for 4xx/5xx enrichment (small, ~50 LOC).

### 9.2 CHANGELOG conventions

`CHANGELOG.md` carries TWO top-level sections during this
cycle:

- `[agentic — Unreleased]` and `[agentic — 2.6.0+agentic.N]`
  for orchestrator-side changes.
- `[Unreleased]` and `[2.6.X]` for RKA-side changes.

When agentic absorbs `main`, the CHANGELOG merge resolution
keeps `[agentic]` entries at the top (most recent first),
followed by `[2.6.2]`, `[2.6.1]`, `[2.6.0]`.

### 9.4 Versioning convention

| Branch | Version field | Format |
|---|---|---|
| agentic | `orchestrator/pyproject.toml` | `2.6.0+agentic.N` (PEP 440 local-version segment) |
| main | `pyproject.toml` + `rka/__init__.py` | `2.6.N` |

The agentic `+agentic.N` local-version segment is intentional
— it makes clear at any point that the agentic branch
diverges from `main` and carries orchestrator-side additions
that are NOT in `main`. Per existing convention since
`v2.6.0+agentic` shipped on 2026-05-30.

## 11. Open Questions

- **Q1.** Should Layer 4 (PI diagnostic surface) split into a
  separate commit-within-PR or bundle with Layers 1-3? The
  design recommends bundling; the PI may prefer separate
  commits for review-surface clarity. **Default: bundle.**
- **Q2.** Should the watchdog patch (PR1) include the
  `_route_after_pi_decision` dead-end fix (Phase-X² sibling
  bug)? They share the routing-helper file but are otherwise
  orthogonal. **Default: keep separate** — `pi_decision_
  select` is the TWO-TAP autonomy-licensing gate and its fix
  deserves isolated review for autonomy-contract implications.
- **Q3.** v2.6.1 + v2.6.2 vs single v2.6.1 release? The split
  separates concerns (schema hygiene vs response
  enrichment); the single release simplifies release-cycle
  overhead. **Default: split** — per PI scope decision
  ("v2.6.1, 2.6.2, etc.").
- **Q4.** Should the v2.6.x cycle include any of the
  deferred-followups (e.g., ID-prefix validator,
  `_route_after_pi_decision` fix)? The audit's
  recommendation is NO — those land in their own PRs after
  v2.6.x stabilizes.
- **Q5.** Adversarial-review workflow on each PR — single
  lens or multi-lens? Phase-X² polish used multi-lens (4
  parallel reviewers). The PR1 + PR2 diffs are smaller;
  single-lens may suffice. **Default: multi-lens for PR2
  (touches LLM-facing surface); single-lens for PR1
  (mechanical refactor + watchdog).**
